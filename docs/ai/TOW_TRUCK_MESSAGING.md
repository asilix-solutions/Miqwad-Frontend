# Tow Truck communication audit and incremental refinement

## Baseline and scope

Base commit: `a6599c5761c33caebd9462fbb461d6b1fdb4e816`.
Required baseline tree: `f7bfd2bc1a9336a7af355f9e14b1c3a5fd9c074e`
(exact Phase 1 + incremental Phase 2 + initial assignment). The three input patches
were hash-verified, applied in order and checked against all three recorded trees.
No implementation commits or live backend mutations were made.

Audit performed before editing: queue, dialog, detail, driver selection, RHF/Zod
fields, review, shared Orders assignment method, AppError normalization, submission
orchestration, Query/session journal and bilingual dictionary. Shared Orders
status translations remain unchanged; they describe recorded order status, not
verified trip progress. No backend availability, realtime or payment state was inferred.

## Findings and decisions

- Every HTTP 409 previously became `assignmentConflict`, losing the verified
  busy-driver reason. Only status 409 plus the exact verified Arabic message
  (surrounding whitespace allowed) now maps to `assignmentDriverBusy`.
- No stable backend busy code has been provided. Different wording, additional
  text, missing/malformed message or another status never implies driver busy.
  Unknown conflict text does not assert that only order status caused the conflict.
- The shared AppError constructor coerces malformed values into strings. The
  assignment request now preserves inherited Axios transforms and sanitizes a
  non-string message locally before shared error normalization. Shared Axios/auth
  code is unchanged. Array/object coercion cannot impersonate the verified message.
- Raw `errors` / `fields` were previously displayed verbatim. They are no longer
  placed in UI state. Only controlled translation keys reach feedback rendering.
  Explicit success:false is a rejection without inventing HTTP 422.
- 400 format rejection, 401 session, 403 permission, 404 missing reference,
  409 conflict and 422 validation now have different actionable explanations.
- Network, timeout, 5xx, malformed acknowledgment and unknown exceptions retain
  uncertain-outcome recovery with controlled context. Acknowledged PUT followed
  by GET failure explicitly reports a display-refresh problem, not failed assignment.
- Driver identity, wrong role and inactive account have distinct feedback. An active
  account is not availability. Busy evidence applies to the rejected attempt;
  selecting a different driver changes the feedback to past-attempt wording.
- Missing, invalid, sub-minimum and unrepresentable cost are separate. Duration
  missing/overlong feedback is inline. No currency rounding/business limit was invented.
- Known rejection preserves the form, order and open dialog. Prior confirmation is
  removed; changing fields/driver invalidates review. A submitted review object
  cannot be reused. New review means fresh GETs and a new explicit confirmation.
- A rejected busy-driver selection must change before review. This is a local
  response to that rejection, not a permanent or global driver availability flag.
- Next-step copy respects assignment/initial eligibility and missing trip data.
  An assigned or non-waiting order is not invited to prepare another initial quote.
- Removed five unused legacy keys implying that all dispatch writes are blocked,
  conflating invalid links/types, or duplicating now-specific field validation.

## Placement, trigger and severity register

The inventory below covers every pre-existing Tow Truck dictionary key plus additions.
For retained rows, the original wording is also the final wording. AR/EN are reviewed
as a pair. Group names link each message to its trigger, business meaning and placement:

| Group                             | Trigger / meaning / placement / assessment                                                                                                                                                                                                                                                                     |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Navigation / queue labels         | Queue or detail is open; headings, link names, pagination and explicit server total. Neutral; retain clear labels and no invented operational counters.                                                                                                                                                        |
| GET / refresh / empty             | Pending read, explicit refresh, empty server page, invalid route or failed GET. Skeleton status, contextual alert with retry, stale data warning retained alongside content. Authentication/permission/missing/invalid-type explanations replace generic guidance when known. Never render raw exception text. |
| Order / payment / next action     | Recorded enums and nullable payment fields; detail/queue status rows and next-action section. Neutral informational labels; Unknown remains Unknown, Pending means awaiting customer payment only. Missing trip data prompts verification.                                                                     |
| Detail / route / missing data     | Presence/absence/validity of server fields and attachment URLs. Section labels, inline hints and restrained route warnings. Missing is not zero, inactive, unavailable or paid. Retained wording is accurate with source projection.                                                                           |
| Draft / permissions / eligibility | Draft navigation, available permissions, initial order/driver/payment eligibility. Local form notices or explicit discard decision. Initial assignment remains separate from unavailable reassignment/removal.                                                                                                 |
| Driver selection                  | Driver list read, active-account eligibility, selected identity, failed/changed driver read. Section loading/error/radio feedback and inline required selection. No online or availability indicator.                                                                                                          |
| Quote fields / review             | Zod validation, local edits, fresh GET review, stale snapshot or explicit confirmation. Inline field errors with descriptions; review heading and contextual warning. Clear next action; no automatic submission.                                                                                              |
| Submission / recovery             | Mutation phase, known rejection, uncertain transport outcome, authoritative reconciliation or explicit outcome check. Persistent workflow summary; rejected is an alert, other phases a status. Focus only follows a user-initiated submit/check. Retry is never automatic.                                    |

## Validation and limitations

- Offline transport is stubbed; no live GET/PUT/DELETE was used for these tests.
  The user supplied the live 200 success and exact busy-driver 409 evidence.
- Regression scenarios cover exact/unknown/malformed conflict, raw detail suppression,
  draft input preservation, changed proposal, consumed confirmation, double click,
  400/401/403/404/422, uncertain recovery, acknowledged-write/failed-read, session
  marker, current permissions, role/account, numeric precision, localization parity,
  request transforms, explicit rejection and malformed success envelopes.
- Draft persistence remains in-memory within the mounted request, not durable across
  reloads or sign-out. Only the existing pending-outcome marker survives reload.
  The UI only claims draft preservation when this page actually has a dirty form.
- Source review preserves Radix focus trap, Escape/dirty guard, focus return, backdrop,
  body lock and scrolling. Feedback adds focus outline, logical border and wrapping;
  no animation was added. A rejected submit focuses the summary, with an explicit
  button to reach driver selection. Background reads never request that focus.
- Source responsiveness assessment: existing 320/360/390 single-column, 768 tablet,
  1024/1280/1440+ wide layouts are retained. New feedback wraps and does not introduce
  fixed minimum widths. RTL logical spacing and AR/EN interpolation are preserved.
- Browser visual/keyboard/screen-reader checks: **BLOCKED BY ENVIRONMENT**; Chromium
  executable is missing. No browser installation was attempted. Source review is not
  evidence of visual verification at any width.
- Reassignment, paid reassignment, unassignment, payment, GPS and realtime remain
  unavailable. Backend concurrency is still authoritative; preflight cannot eliminate
  a race between the final GET and PUT. No backend idempotency guarantee was invented.
- The increment must be applied over the exact three-layer baseline, not plain main.
  Patch applicability and resulting tree are independently verified using temporary
  Git indexes outside the repository, without changing the real index or stash.
